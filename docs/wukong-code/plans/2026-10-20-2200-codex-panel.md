# Codex Git Graph conversation panel implementation plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use wukong-code:subagent-driven-development or wukong-code:executing-plans to implement this plan task-by-task.

**Goal:** Open the existing read-only Git graph as a local MCP App conversation panel, without an ordinary browser tab or HTTP service.

**Architecture:** Bundle a local stdio MCP server and a self-contained HTML app. Reuse repository.ts, renderGraph and the existing graph interactions. Keep HTTP mode as an explicit fallback. Bind each graph handle to a canonical repository for the process lifetime; UI reads use the opaque graph handle, never an arbitrary path.

**Tech Stack:** Node.js >=22, TypeScript 5.6.3, esbuild 0.25.12, official @modelcontextprotocol/sdk 1.32.1, existing Node test runner.

## Global constraints

- Read-only Git whitelist, LC_ALL=C, 10 second Git timeout, page size 50; details 50 files/4000 chars, diff 30000 chars.
- No HTTP server, external resource, network fetch, localhost token or terminal daemon needed for MCP panel mode.
- Install under a new Codex marketplace/plugin identity; preserve Claude manifests and versions.
- Default target comes from a single file root advertised by the host, or the process working directory when it is outside the plugin package. Explicit repository arguments always win. If ambiguous, require an explicit repository; never silently show the installed plugin checkout.
- All user-facing repository content remains escaped by the existing render layer. Support empty/non-repo/error states.
- Skill invocation remains quiet on success and reports actual open/verification failures; never silently fall back to an ordinary browser tab.
- New plugins need a newly loaded conversation. Do not claim desktop rendering from protocol checks alone.

## Task 1: Local MCP repository service

Files: create codex/mcp-server.ts, codex/mcp.ts, codex/mcp.check.ts; modify codex/package.json, package-lock.json, tsconfig.json.

Interface: createGraphMcpServer(options?: {defaultRepository?: string; readPanel?: () => Promise<string>}): Server. Tool open_git_graph({repository?: string}) returns structuredContent {graphId,repository,branches,current,commits,hasMore}; attaches the UI resource ui://cc-git-graph/panel-v1.html and openai/ui thread entrypoint. Tool read_git_graph({graphId,operation:'branches'|'commits'|'detail'|'diff',branch?,remote?,offset?,hash?,path?}) returns structuredContent {data}; app-only, read-only. Graph IDs are process-private capabilities, canonical roots are fixed per graph. Unknown graph IDs, operations, hashes, paths and missing target fail clearly. Resource reads return self-contained HTML with text/html;profile=mcp-app and fullscreen metadata.

Interface: mountGraph(api: <T>(path:string,query?:Record<string,string>)=>Promise<T>):void preserves existing graph behavior.
